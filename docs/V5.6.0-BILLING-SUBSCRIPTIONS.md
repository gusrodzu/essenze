# v5.6.0 — Billing & Subscriptions

## Comportamiento comercial

### Upgrade
Se aplica inmediatamente.

El sistema calcula:

- crédito por el tiempo no consumido del plan actual;
- costo proporcional del nuevo plan;
- cargo neto = nuevo proporcional - crédito.

La fecha de renovación del ciclo actual se conserva.

### Downgrade
No se aplica inmediatamente.

El cliente conserva el plan ya pagado hasta `currentPeriodEnd`.
El nuevo plan queda guardado en `scheduledPlanId` y se aplica al comenzar el próximo ciclo.

### Ciclo mensual / anual
La suscripción registra `billingCycle`.

El anual utiliza `annualPrice`. El mensual utiliza `monthlyPrice`.

## Pagos

La versión incorpora la arquitectura de billing, pero no captura datos sensibles de tarjeta.
`BillingPaymentMethod` almacena únicamente referencias tokenizadas del proveedor, marca y últimos 4 dígitos.

La integración real con Mercado Pago debe implementar:

1. creación/tokenización del método;
2. cobro de invoice;
3. webhooks;
4. reintentos;
5. PAST_DUE/SUSPENDED;
6. conciliación de payment attempts.

## Base de datos

Hay nuevos modelos y relaciones. Ejecutar `db:generate` y luego `db:sync`.
Nunca ejecutar `prisma migrate reset`.
