# v5.5.3 — Ciclo de facturación

## Regla de producción

Cuando una empresa cambia de plan:

1. El nuevo plan se aplica de inmediato.
2. El usuario elige un día de corte/pago entre 1 y 28.
3. El periodo inicial corre desde el momento del cambio hasta el siguiente corte.
4. El plan queda bloqueado hasta el próximo corte.
5. Antes de esa fecha, otro cambio devuelve `409 PLAN_CHANGE_LOCKED`.
6. En la siguiente fecha de facturación vuelve a estar permitido cambiar.
7. Los módulos habilitados/deshabilitados se sincronizan con el nuevo plan en ese mismo momento.

## Ejemplo

Cambio: 2 de septiembre
Día de pago elegido: 15

- Nuevo plan activo: 2 de septiembre
- Próximo corte: 15 de septiembre
- Cambio bloqueado hasta: 15 de septiembre

Si cambia el 15 de septiembre y conserva día 15:

- Nuevo plan activo: 15 de septiembre
- Próximo corte: 15 de octubre
- Bloqueado hasta: 15 de octubre

## Actualización de base

Esta versión agrega campos a `CompanySubscription`, por lo que requiere:

```powershell
npm run db:generate
npm run db:sync
```

Si Prisma advierte pérdida de datos, detén el proceso y revisa el mensaje. No uses `migrate reset`.
